# Presentation maintenance checklist

- Read the current CoderSkills Git Project Harness before substantial documentation updates.
- Preserve the project-specific layout: tables for catalogs, commands and a capability matrix for tools.
- Keep the existing header unless a better project-specific replacement is reviewed. Never invent screenshots.
- Update all five reading guides when scope or usage changes; clearly state untranslated corpus or UI boundaries.
- Keep upstream links and license distinctions; never infer permission from a public repository.
- Rank only using dated evidence. Historical trend data must not be presented as current.
- Validate local links and run the repository tests/build before opening a separate PR.
- Review rendered README at desktop and mobile widths before claiming visual verification.
- SEO means accurate purpose, useful headings, stable links, and truthful descriptions, not keyword stuffing or guaranteed rankings.
